# 功能表计划

## 背景

当前系统管理 Issue，但 Issue 往往对应某个具体的**功能/特性**（function/feature）。这些功能定义可能来自不同平台（如"游戏软件"、"教学软件"等），每个平台有自己的功能 ID 体系。

目标：建立统一的 `poiFunctions`（phoenix open issue functions）表，作为跨平台功能的单一数据源，Issue 可关联到某个功能条目，实现功能维度的 Issue 追踪。

## 数据模型

### poiFunctions 表

| 列 | 类型 | 必填 | 说明 |
|----|------|------|------|
| `id` | TEXT PK | ✅ | UUID |
| `platform` | TEXT | ✅ | 来源平台名称 |
| `externalId` | TEXT | ✅ | 来源平台的 ID |
| `functionName` | TEXT | ✅ | 功能名称 |
| `targetYear` | TEXT | — | 目标年份 |
| `clientGroup` | TEXT | — | 客户群体 |
| `developGroup` | TEXT | — | 开发组 |
| `createdAt` | TEXT | — | 创建时间 |
| `updatedAt` | TEXT | — | 更新时间 |

**唯一约束：** `UNIQUE(platform, externalId)` — 同一平台下的 ID 不能重复。

### issues 表扩展

在 `issues` 表新增一列：

| 列 | 类型 | 说明 |
|----|------|------|
| `functionId` | TEXT NULL | 关联 poiFunctions.id |

- 不冗余存储 `functionName`，通过 LEFT JOIN 获取，避免重命名时的同步问题。
- Issue 列表查询时通过 JOIN `poiFunctions` 附带 `functionName`（别名为 `_functionName`）。
- **Issue 列表新增「功能」列**，直接显示 `_functionName`。

## 纯算法（packages/core/src/algorithms/）

以下纯函数从 UI/DB 中剥离，零依赖，可独立进行 vitest 单元测试：

### `mapXlsxRow(raw)` — XLSX 行映射

- 输入：xlsx 解析后的原始行对象（支持中文/英文/驼峰列名）
- 输出：规范化的 `CreatePoiFunctionInput`
- 处理：列名匹配、去空格、数字转字符串

### `diffImportRows(existing, incoming)` — 导入差异检测

- 输入：已有记录列表 + 待导入列表
- 输出：`{ toInsert, toUpdate }` — 拆分为新增和更新两组
- 规则：`(platform, externalId)` 匹配到已有 → update；否则 → insert

### 单元测试（vitest）

**根级配置：** `vitest.config.ts` — include `packages/core/src/**/*.test.ts`（已有）+ `tests/**/*.test.ts`（新增）
**测试文件：** `tests/algorithms/function-import.test.ts`
**运行：** `pnpm test`

> **TODO（后续迁移）：** 将 `packages/core/src/algorithms/push.test.ts`、`permission.test.ts`、`scheduling.test.ts` 迁移到 `tests/algorithms/`，统一管理。

| 函数 | 用例数 | 覆盖场景 |
|------|--------|----------|
| `mapXlsxRow` | 7 | 中文列名、英文列名、驼峰列名、去空格、空输入、可选字段、数字 id |
| `diffImportRows` | 5 | 全部更新、全部新增、混合、空输入、空已有 |

运行：`pnpm test`（从根目录一次跑完所有测试）

## 功能范围

### 1. 功能管理页面（`/functions`）

- 在 Ribbon「系统」标签下新增「功能」入口
- 显示所有功能条目的表格（platform, externalId, functionName, targetYear, clientGroup, developGroup）
- 支持增、删、改、查

### 2. XLSX 导入

- 在功能页面和设置页面均可导入 `.xlsx` 文件
- 使用 `xlsx` 包在前端解析 → `mapXlsxRow()` 标准化 → 预览 → 确认 → 批量写入后端
- 后端用 `diffImportRows()` 分类后事务写入
- 导入策略：同一 `(platform, externalId)` 已存在则更新，否则新增

### 3. JSON 导出

- 导出全部功能数据为 JSON 文件

### 4. Issue 关联功能

- Issue 创建/编辑时可选择关联功能（下拉搜索）
- **Issue 列表新增「功能」列**，显示 functionName（通过 JOIN 获取）
- Issue 详情展示关联的功能名称（通过 JOIN 或 store 查询）
- 删除功能时自动解除关联（`functionId` 置 NULL）

### 5. 数据备份集成

- `poiFunctions` 表纳入整库备份/恢复范围

## 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| functionName 存储 | 只在 poiFunctions 存，issues 通过 JOIN 查 | 避免重命名同步问题 |
| 导入格式 | 仅 XLSX（xlsx 包前端解析） | 用户要求 |
| 列名映射 | 纯算法 `mapXlsxRow()` | 无 UI/DB 依赖，可独立测试 |
| 导入差异检测 | 纯算法 `diffImportRows()` | 同上 |
| 删除级联 | 手动 NULL（非 FK） | 与项目 PRAGMA foreign_keys = OFF 一致 |
| 导入冲突 | Upsert（存在则更新） | platform+externalId 唯一 |
