# 数据字典配置

数据字典用于定义 Issue 的下拉选项枚举值，共 7 个分组。管理员可在「设置 → 数据字典」页面管理。

## 唯一性规则

**所有分组**（点检表类型、重要度、紧急度、问题分类、发现阶段、组织类型、关闭理由）**同一分组内 `value`（字段值）不可重复。**

- 数据库：`UNIQUE(groupName, value)` 索引，适用于全部分组
- 新增/编辑：服务端校验，重复会拒绝
- 历史重复：**启动时尽力去重，失败不阻塞登录**；请 **设置 → 数据库修正 → 数据字典补全**（或数据字典页「去重」）完成修正

### 去重规则

同 `(groupName, value)` 有多行时：

1. **保留一条**：`core` 标签优先 → `enabled=1` 优先 → `sortOrder` 最小 → `id` 最小
2. **合并 tags**：被删行的标签并入保留行
3. **删除其余行**

**不影响业务引用**：Issue、列表、组织等存的是字典 **value**（如 `function`、`monthly`），不是 `dict.id`，去重后引用仍然有效。

服务端：`DictService.dedupe()` / `POST /dict/dedupe`；底层 `dedupeDictEntries(db)`。

## 标签列（存储格式）

`tags` 为**可选、可多个**的标签列表。数据库中统一存为 **前后带逗号** 的格式，便于精确筛选（含首尾标签）：

| 场景 | 存储值 |
|------|--------|
| 无标签 | `''`（空字符串） |
| 单标签 `automotive` | `,automotive,` |
| 多标签 core + general | `,core,general,` |
| 三标签 | `,automotive,software,general,` |

### 为何前后加逗号

旧格式 `core,general,automotive` 用 `LIKE '%automotive%'` 可能误匹配 `myautomotive`；用 `LIKE 'automotive%'` 又无法区分首尾标签。

新格式下，每个标签在字符串中均为 `,tag,` 子串，因此 **第一个、最后一个、中间任意标签** 都可用同一模式精确匹配：

```sql
-- 含 automotive 标签（不会匹配 automotiveX）
WHERE tags LIKE '%,automotive,%'
```

插件代码侧（`packages/admin-plugin/vue/phoenix-open-issue/core`）：

- `parseDictTags(tags)` — 解析为数组（兼容旧格式输入）
- `normalizeDictTags(tags)` / `formatDictTags(...)` — 规范为 `,tag1,tag2,`
- `hasDictTag(tags, 'automotive')` — 是否含某标签
- `dictTagLikePattern('automotive')` — 生成 SQL LIKE 模式 `%,automotive,%`

### 录入与展示

- **界面/API 输入**：可写 `software,automotive` 或 `,software,automotive,`，保存时服务端统一 `normalize`
- **设置页展示**：解析后显示为 `software, automotive`（不含首尾逗号）
- **应用预设**：若 value 已存在，仅**追加**新标签并重新 normalize，不新建重复行

### 历史数据迁移

旧库若为 `core,general` 格式，在 **服务启动** 或 **设置 → 数据库修正 → 数据字典补全** 时会自动转为 `,core,general,`。

## 分组说明

| 分组 | 用途 | 影响范围 |
|------|------|----------|
| **点检表类型** (listType) | 列表/点检表类型 | 列表创建、仪表盘展示 |
| **问题分类** (issueCategory) | Issue 类别，如功能/外观/安全等 | Issue 创建/编辑、列表筛选 |
| **发现阶段** (detectionPhase) | 问题在哪个阶段发现 | Issue 创建/编辑、详情展示 |
| **组织类型** (orgUnitType) | 组织节点类型 | 组织架构管理 |
| **重要度** (severity) | 业务影响/重要程度；`severity` 为兼容分组名 | Issue 创建/编辑、列表筛选 |
| **紧急度** (priority) | 处理时效要求；`priority` 为兼容分组名 | Issue 创建/编辑、列表筛选与排序 |
| **关闭理由** (closeReason) | 关闭 Issue 时的原因 | Issue 关闭操作 |

### 点检表类型标签约定

内置四项（年度/月度/项目/自定义）仅打 **`core`**，**不打 `general`**。扩展项（个人/小组/科室/部门/公司）打 **`general`**。

| 值 | 显示名 | 标签 |
|----|--------|------|
| `yearly` | 年度 | `core` |
| `monthly` | 月度 | `core` |
| `project` | 项目 | `core` |
| `custom` | 自定义 | `core` |
| `personal` | 个人 | `general` |
| `group` | 小组 | `general` |
| `department` | 科室 | `general` |
| `division` | 部门 | `general` |
| `company` | 公司 | `general` |

启动或「数据字典补全」会自动修正旧库中内置项误带的 `general` 标签。

### Issue 二维内置字段

Issue 使用“重要度 × 紧急度”二维模型。两组均为 `core,general` 内置字典：固定四档，不允许新增、删除、停用、调整顺序或修改 `value`，管理员只可修改显示名。数据字典、选择弹窗和文档均按低到高排列。

| 产品维度 | 兼容分组/字段 | 固定值（低 → 高） | 默认显示名（低 → 高） |
|---|---|---|---|
| 重要度 | `severity` | `trivial` / `minor` / `major` / `fatal` | 较低 / 一般 / 重要 / 关键 |
| 紧急度 | `priority` | `low` / `medium` / `high` / `critical` | 可延后 / 正常 / 尽快 / 立即 |

兼容字段名用于保持现有数据库、API 和排序配置稳定，不代表汽车 FMEA 语义。汽车 FMEA 严重度是独立的 S1–S10 专业量表；行动优先级 AP 由 S/O/D 组合得出，后续应作为附属功能实现，不能复用本表四档值。

## 标签系统

每个字典项都有「标签」列，用于标记来源预设（汽车/软件/通用/内置等）。**库内存储格式见上文「标签列（存储格式）」**。

| 标签 | 含义 |
|------|------|
| `core` | 内置项，不可删除 |
| `general` | 通用扩展项（如点检表类型中的个人/小组/公司等；**内置四项不带此标签**） |
| `automotive` | 来自汽车默认值预设 |
| `software` | 来自软件默认值预设 |
| （空） | 手动添加、未打标签 |

**标签行为：**

- 点击预设按钮追加新项 → 打上对应标签（存为 `,automotive,` 等）
- 预设 value 已存在但无该标签 → 追加标签（不重复插入）
- 预设 value 已有该标签 → 跳过
- 手动添加 → 标签可为空；保存时 normalize
- **按标签批量删除**（🗑 删除一类值）：SQL `LIKE '%,tag,%'` + `hasDictTag` 二次校验

## 删除保护

删除字典项时，系统会自动检查该项是否被其他数据引用。如果正在使用中，会**阻止删除**并显示使用情况。

| 字典分组 | 引用表 | 引用列 |
|----------|--------|--------|
| 问题分类 | `issues` | `category` |
| 发现阶段 | `issues` | `detectionPhase` |
| 重要度 | `issues` | `severity` |
| 紧急度 | `issues` | `priority` |
| 关闭理由 | `issues` | `closeReason` |
| 组织类型 | `orgUnits` | `unitType` |

**示例：** 删除"功能 (function)"时，如果有 3 条 Issue 的分类为 `function`，则返回：
> 无法删除：Issue 问题分类: 3 条

## 推荐实践

1. **新项目启动**：先点「汽车默认值」再点「软件默认值」，保留两套值的并集；重复项自动跳过
2. **汽车电子团队**：汽车默认值已覆盖 IATF 16949 基本分类需求，软件默认值作为补充
3. **纯软件团队**：只用「软件默认值」即可，汽车相关项可手动删除

## 插件真源

产品字典的默认值、可定制字段和预设标签由 `packages/admin-plugin/manifest.json` 的 `dictionaryContributions` 声明，Node 维护服务负责 reconcile。修改预设时必须同步 manifest、字典契约测试与 migration/ledger 规则，不能只改页面常量。
