# 列表成员与负责人 — 设计讨论稿

> 状态：**已定稿（2026-07-09）** — 允许多名所有者；主负责人单独标识。

---

### 已定规则（2026-07-09，Q1–Q5 确认）

| 问题 | 决定 |
|------|------|
| **Q1** 需要 owner 角色？ | ✅ 保留；添加成员时可选「所有者」 |
| **Q2** 转让对象必须是成员？ | ✅ 是；非成员须先添加为成员 |
| **Q3** 设为主负责人后原主负责人权限？ | ✅ **不降级**，仅变更 `ownerId` 标识 |
| **Q4** 多个 owner？ | ✅ 允许多名所有者并存 |
| **Q5** 非 owner 能否转让？ | ❌ 不能；仅 **owner 角色** 成员可「设为主负责人」 |

补充规则：

- **主负责人**（`issueLists.ownerId`）唯一：列表页展示、推送审批。
- **当前成员表格**可 inline 编辑权限（下拉）；添加区仍可新选角色。
- **admin** 可管理普通成员权限，但不能改 owner 角色 / 不能转让主负责人。
- **系统管理员**（`users.systemRole = admin`）：即使**不是列表成员**，也可添加/移除成员、修改权限、设主负责人（与列表编辑改负责人一致）。
- **移除 owner**：至少保留一名；**主负责人不可移除**，须先设其他主负责人。

## 1. 两个容易混淆的概念（保留说明）

系统中与「谁负责这个列表」相关的数据有两层：

| 概念 | 存储位置 | 含义 | 数量 |
|------|----------|------|------|
| **负责人**（主 owner） | `issueLists.ownerId` | 列表的**唯一**法定负责人；推送审批、对外展示「负责人」列均以此为准 | **1 个** |
| **成员角色 owner** | `issueListMembers.role = 'owner'` | 成员权限等级，表示「所有者级权限」 | **可多个** |

### 当前问题

1. **展示不一致**：成员表里可以有多个 `role=owner`，但列表页「负责人」列只显示 `issueLists.ownerId` 对应的人。
2. **添加成员时选「所有者」**：只改成员表，**不会**更新 `issueLists.ownerId`，导致负责人列与成员表对不上。
3. **「转让」按钮位置混乱**：每个 owner 成员行都显示「转让」，点击某行 = 把主负责人转给**该行用户**；用户难以理解「我是要转给别人，还是点别人那行？」。
4. **移除 owner**：后端允许在有多个 owner 成员时移除「其他 owner」，但不会自动修正 `issueLists.ownerId`。

## 2. 建议统一的原则（待确认）

### 原则 A：单一主负责人

- 每个列表**有且只有一个**主负责人（`issueLists.ownerId`）。
- 成员角色里的 `owner` **建议取消或改名为与主负责人绑定**，避免「多个 owner 角色」与「一个负责人字段」并存。

> **备选**：保留多 owner 角色，但规定「主负责人必定是 owner 成员之一，且只有主负责人在 UI 上显示为负责人」。  
> 若选此方案，需在所有变更路径同步两处数据。

### 原则 B：转让 = 更换主负责人

- **转让**只改变 `issueLists.ownerId`，不是泛泛地「加/减 owner 角色」。
- 操作者必须是**当前主负责人**（或系统管理员 `admin`）。
- 转让后：原主负责人 → `admin`（或 `editor`，待定）；新主负责人 → 若不在成员中则自动加入，角色为 `owner` 或 `admin`（若取消 owner 角色则统一用 `admin`）。

### 原则 C：添加/移除成员与负责人分离

| 操作 | 入口 | 谁可操作 |
|------|------|----------|
| 添加普通成员（editor/viewer/reporter） | 成员弹窗 · 添加区 | owner、admin |
| **转让主负责人** | 成员弹窗 ·「转让给他人」 | 当前主负责人、系统 admin |
| 移除普通成员 | 成员行 ·「移除」 | owner、admin |
| 移除其他 owner 成员 | ❌ 不建议单独存在 | — |
| 编辑列表 · 改负责人 | 列表管理 · 编辑（admin / owner / admin 角色） | 与转让同一后端逻辑 |

## 3. 建议的 UI 交互（待确认）

### 3.1 成员管理弹窗（已实现）

```
┌─ 管理成员 ──────────────────────────────────────────┐
│ 当前成员（表格）                                     │
│  成员 | 权限▼ | 标识      | 操作                   │
│  张三 | 所有者 | 主负责人  | —                      │
│  李四 | 编辑者▼| —         | [设为主负责人] [移除]   │  ← 仅 owner 可见转让
│ ── 添加成员 ──                                      │
│  [用户▼] [角色▼含所有者] [添加]                       │
└─────────────────────────────────────────────────────┘
```

- **权限列**：owner/admin 可改；owner 可授予/撤销 owner；admin 不能动 owner 行。
- **设为主负责人**：仅 owner 角色成员可操作；目标须已是 owner 成员。

### 3.2 转让流程

1. owner 成员对另一名 **owner** 成员点击「设为主负责人」。
2. 确认后：仅 `ownerId` 变更；原主负责人及其他成员**权限级别不变**；若新主负责人非 owner 则升为 owner。

---

- 编辑弹窗中的「负责人」下拉：与转让共用后端逻辑（改 `ownerId` + 同步成员）。
- 仅 **系统 admin / 列表 owner 角色 / admin 角色** 可编辑（与现有权限一致）。

## 4. 角色权限矩阵（建议稿）

与[当前路线](./current-roadmap.md)对齐，并明确**负责人相关**操作：

| 操作 | 主负责人 | admin 成员 | editor | 系统 admin |
|------|:--------:|:----------:|:------:|:----------:|
| 查看成员 | ✅ | ✅ | ✅ | ✅ |
| 添加成员（非负责人） | ✅ | ✅ | — | ✅ |
| 移除普通成员 | ✅ | ✅ | — | ✅ |
| **转让主负责人** | ✅ | — | — | ✅ |
| 编辑列表 · 改负责人 | ✅ | ✅ | — | ✅ |
| 删除列表 | ✅ | — | — | ✅ |

说明：

- **editor 不能管理成员**（与 `canAddMember` 一致：仅 owner/admin）。
- **admin 成员不能转让**（转让是「放弃主负责人身份」，只能由当前主负责人或系统 admin 执行）。
- 系统 admin 可在列表管理页直接改负责人，无需先成为成员（后端 `assignOwner` 已实现：自动加入成员）。

## 5. 数据一致性规则（建议实现）

在**加载列表**、**保存成员**、**转让**、**编辑负责人**时执行：

1. `issueLists.ownerId` 必须指向存在的用户。
2. 主负责人必须是成员；若不是则自动加入。
3. 主负责人在成员表中应有最高权限角色（`owner` 或 `admin`，取决于是否保留 owner 角色）。
4. **不再允许**通过「添加成员 + 选所有者」增加第二个 owner 而不更新 `ownerId`。
5. 若成员表中 `role=owner` 的用户与 `ownerId` 不一致，以 **`ownerId` 为准** 修复成员角色（已在 `syncOwnerIntegrity` 中部分实现）。

## 7. 与现有 API 的对应关系

| 用户操作 | API | 备注 |
|----------|-----|------|
| 转让给他人 | `PATCH /list/:id/transfer-owner` `{ userId }` | 目标须已是成员（当前限制） |
| 编辑列表改负责人 | `PUT /list/:id` `{ ownerId }` | admin/owner 可用；可转给非成员（admin） |
| 添加成员 | `POST /list/:id/member` | 建议前端禁止 role=owner |
| 改成员角色 | `PATCH /list/:id/member/:userId/role` | owner 才能授予/撤销 owner 角色 |
| 移除成员 | `DELETE /list/:id/member/:userId` | 不能移除最后一个 owner；不能移除自己 |
