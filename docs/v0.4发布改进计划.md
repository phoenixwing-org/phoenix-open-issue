# v0.4.0 发布改进计划

## 目标

将当前功能原型收敛为可部署到 Linux、可供内部用户持续测试的发布基线。判断标准：

1. `pnpm test` 全部通过。
2. `pnpm build` 全部通过。
3. `node packages/server/dist/main.js` 可启动，`/health` 返回成功。
4. 升级不依赖删库，数据库迁移可重复执行。
5. 业务数据不会通过公开操作被物理删除。
6. 数据库文件有明确的持久化、备份和恢复流程。

## 本轮完成

- 统一项目和 workspace 版本为 `0.4.0`。
- 修复 Express 5 路由参数类型、异步路由包装器和 Router 声明。
- 在 server 内建立稳定 SQLite Adapter 边界，生产构建不再依赖未编译的依赖子路径。
- 数据保护下沉到后端：列表软删除、Issue 取消、点检跳过、组织拒绝删除、功能/字典停用。
- 修复 Issue 编号索引同名冲突，增加重复检测和幂等唯一索引建立。
- 增加临时 SQLite 后端集成测试。
- 补充 Linux 测试部署文档。

## 后续 P1：发布后首轮

- Auth、列表权限、推送审批、备份恢复的后端集成测试。
- Playwright 冒烟测试：登录、建列表、建 Issue、点检、推送审批。
- 增加统一审计日志：操作人、动作、目标、时间、变更前后值。
- 功能和字典增加“已停用”管理视图与恢复操作。
- 组织节点增加正式的 `enabled` 字段，替代名称前缀约定。

## 后续 P2：性能与运维

- 拆分前端主包，降低 Element Plus/phoenix-wing 公共 chunk 体积。
- 增加数据库定时备份、保留周期和恢复演练。
- 增加结构化日志、请求 ID 和错误追踪。
- 在 10–50 人并发场景下执行 SQLite 写入压力测试。

## 暂缓

- PostgreSQL / cool-admin 迁移。
- npm UI 包拆分。
- 大规模全文检索。

这些工作应在内部测试反馈稳定后启动，避免同时改变业务模型和基础设施。
