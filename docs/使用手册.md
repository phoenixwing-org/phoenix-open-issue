# Open Issue 插件使用手册

本文只说明 Phoenix Admin 中的 Open Issue 插件。账号、登录、组织、全局导航、备份和插件生命周期由 Host 管理，不在本插件中提供第二套实现。

## 进入插件

插件登记、安装、启用并分配 capability 后，从 Phoenix Admin 的业务区进入 Open Issue。可见入口包括仪表盘、列表、推送历史、8D 报告和功能表；Issue 详情与列表详情也支持深链打开。

入口是否可见由插件 capability 与 Host 角色共同决定。看不到入口时先检查插件状态和 capability，不要在产品源码中增加绕过权限的菜单。

## 列表与成员

- 列表可按年度、月度、项目或自定义类型组织。
- 创建者成为 owner；owner 可编辑列表、管理成员和转让负责人。
- admin 可管理列表设置和成员；editor 可维护 Issue 与点检；reporter 只能新建 Issue；viewer 只读。
- Host 的系统只读上限优先于列表角色；拥有较高列表角色也不能绕过系统 capability。
- 归档和软删除是两种状态：归档是日常整理，软删除只允许系统管理员恢复。

详细规则见[列表成员与负责人](列表成员与负责人.md)和[多人权限与列表筛选](多人权限与列表筛选加固.md)。

## Issue

Issue 的主要字段包括标题、重要度、紧急度、分类、发现阶段、提出人、责任人、状态、截止日和关联功能。列表支持简单、复杂、跟踪三种视图，以及筛选、排序、分页和列设置。

重要度表示业务影响，紧急度表示处理时效。8D 是独立附属报告，不写入 Issue 核心表单。字段与列设置见 [Issue 列设计](Issue列设计.md)。

关注度属于“Issue 与当前列表的关联”，一个列表调整关注度不会影响其他关联列表。设为 0 表示本列表不关注，详情见[关注度与多列表关联](IssueListLink关注系数.md)。

## 点检

每条 Issue 可以添加多条点检记录：

- 点检日必填，用于时间线排序。
- 截止日可选，只负责逾期判断；从截止日次日起仍未完成才算逾期。
- 负责人保存稳定 Host 用户 ID，页面通过 Host 批量解析显示姓名。
- 无截止日是合法状态，不显示逾期。

详见[点检日期设计](点检日期设计.md)。

## 推送

推送建立列表关联，不移动或复制 Issue：

- 推送到列表：选择有权访问的目标列表，由目标列表 owner/admin 处理。
- 推送给用户：接收人接受时再选择自己管理的目标列表。
- 接收人可接受或拒绝；发起人在处理前可撤回。
- Issue 主字段仍由源列表权限控制，目标列表只维护自己的关注度等关联状态。

详见[推送工作流](推送工作流.md)和[仪表盘待办中心](仪表盘待办中心.md)。

## 8D 报告

- 报告可独立存在，也可通过可空 `relatedIssueId` 关联一个 Issue。
- D3、D4、D5-D6 保持专业语义，不挤入通用 Issue 表格。
- 建立或更换关联时必须有目标 Issue 的编辑权限；关联本身不授予额外权限。
- 删除或修复异常关联时保留报告正文，必要时把报告转为未关联状态。

详见[扩展能力与 Issue 关联](附属功能与Issue关联计划.md)。

## 功能表与字典

功能表支持维护、导入与导出，并可被 Issue 引用。产品字典由 manifest 声明并由 Host 物化，业务页面只消费插件所属字典和 Host 公开适配器；统一字典维护入口为 `/phoenix/dictionary-maintenance`。详见[数据字典配置](数据字典配置.md)。

## 系统维护与受控测试

系统维护统一进入 Host 的 `/phoenix/maintenance`。Open Issue 不提供第二套维护页面、恢复/收回/关闭 chrome 或私有维护 endpoint；业务修正规则等待 Host adapter schema 冻结后，以声明式、可审计、幂等、可重试的描述接入。

受控测试通过仓库 `pnpm admin-plugin:test-core` 或完整 `pnpm admin-plugin:verify` 门禁运行固定白名单，不接受页面输入命令、目录或测试路径。生产不允许用 TypeORM `synchronize` 或开发 seed 代替 migration。

## 常见问题

### 推送后源列表的 Issue 会消失吗？

不会。两个列表关联同一条 Issue，主数据由源列表权限控制。

### 为什么只显示用户 ID？

业务表只保存稳定 Host 用户 ID。页面应通过 Host 用户适配器批量解析并显示“姓名（账号）”；未知或已删除用户使用确定性占位并保留 ID。

### 为什么不能直接安装或建表？

插件包含版本化 SQL，正式环境必须先做 migration dry-run、可信备份和受控执行。开发 Link/Junction、自动 `synchronize` 和旧 COOL Hook 安装器都不能替代该流程。

### 如何开发挂载或打包？

见 [Phoenix Admin 插件部署](PhoenixAdmin插件部署.md)。
