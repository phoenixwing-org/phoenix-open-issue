# 仪表盘待办中心

状态：current

Owner：Open Issue maintainers

适用版本：0.6.x

最后核验：2026-08-01

## 目标

仪表盘使用一组平级 Tab 组织“概览”和待办内容，避免在列表概览上方再嵌套一层待办卡片。用户默认进入“概览”；待办区域只负责聚合、提醒和高频快捷动作，完整历史、复杂人员处理和第三方账号关联仍在对应业务页面完成。

本功能不建设通用任务表，不复制推送或审批数据。任务由当前真实业务状态实时投影：推送来自 `pushRecords.status='pending'`，账号审批来自 `users.approved=0`，第三方登录审批来自 `externalBindRequests.status='pending'`。

## Tab 与口径

| Tab | 可见范围 | 数据口径 | 快捷动作 |
|---|---|---|---|
| 概览 | 所有登录用户 | 当前用户可访问的列表；管理员可切换全部列表 | 新建列表、范围/状态筛选、进入列表、归档 |
| 待我处理 | 所有登录用户 | 定向发给当前用户，或发到当前用户担任 owner/admin 的列表；系统查看用户始终为空 | 接受、拒绝 |
| 我发起的 | 所有登录用户 | 当前用户发起且仍为 pending 的推送 | 查看 Issue、撤回 |
| 管理审批 | 仅系统管理员 | 待批准本地账号 + 待关联第三方登录申请 | 批准账号、进入组织架构继续处理 |

系统管理员拥有全局推送处理权限，但该权限本身不会把全系统待处理推送都算作“待我处理”。只有明确发给管理员本人或其实际管理列表的推送才进入个人待办；其他记录仍可在“推送历史”中按管理员权限处理。

同一条推送可能同时出现在“待我处理”和“我发起的”（例如发起人也管理目标列表）。各 Tab 保留各自职责视角；待办中心标题的总数按推送记录 ID 去重后再加管理审批数，避免重复放大总待办。

## 展示与交互

- 页面 Header 在桌面宽度下同行显示“仪表盘”标题、四个视图 Tab 和帮助入口；窄屏允许工具条横向滚动。“新建列表、范围、状态”位于“概览”内部，切换到任务 Tab 后不再显示无关的列表操作。
- 三个任务 Tab 在标题旁显示当前数量；推送 Tab 首屏最多显示最近 5 项，管理审批中的账号和第三方登录类别各显示最近 5 项。
- 超过 5 项时显示剩余数量，并提供“查看推送历史”或“打开组织架构”。
- 首次固定打开“概览”，不会因待办数量抢走用户当前视图。
- 首次只请求待办数量摘要；点击任务 Tab 后才请求该类最多 5 条数据。切离任务 Tab 时立即清空该类数据并通过 `v-if` 销毁内容 DOM，不在前端缓存不可见任务；返回仪表盘时只刷新当前 Tab。
- 定向用户推送点击接受时，继续复用“选择本人 owner/admin 目标列表”的弹窗。
- 账号待批准支持仪表盘直接批准；拒绝、组织调整、角色调整、第三方账号绑定/新建等复杂操作进入组织架构完成。
- 所有空状态都明确说明当前没有哪一类事项，不使用空白占位。
- 待办中心和仪表盘列表卡片均使用 Wing/Element 主题 token，支持白天、黑天和跟随系统。

## API 与权限

`GET /api/dashboard/tasks?tab=summary|incoming|outgoing|admin&limit=5` 需要登录。`summary` 只返回数量；其他值只返回对应 Tab 的数据，其他数组为空：

```json
{
  "scope": "summary",
  "incomingPushes": [],
  "outgoingPushes": [],
  "pendingUsers": [],
  "externalBindRequests": [],
  "counts": {
    "incoming": 0,
    "outgoing": 0,
    "admin": 0,
    "total": 0
  }
}
```

- `tab` 默认是 `summary`；非法值返回 400。`limit` 默认 5，并限制在 1–20。
- 接口只查询 pending 推送，不扫描已处理历史；前端不再一次接收三个 Tab 的明细。
- 非管理员固定返回空的 `pendingUsers` 和 `externalBindRequests`，不能借仪表盘绕过管理员接口权限。
- 推送条目沿用 `_canHandle` / `_canWithdraw` 权限标记；真正执行接受、拒绝、撤回时，原接口仍再次校验权限和 `status='pending'`，不能依赖前端按钮。
- 管理员快捷批准沿用 `PATCH /user/:userId/approve`，服务端继续强制系统管理员权限。

## 验收

- owner/admin 能看到发给本人或本人管理列表的推送；普通 editor 与系统 viewer 不能看到不属于自己的接收待办。
- 发起人能看到并撤回自己的 pending 推送。
- 非管理员看不到管理审批 Tab 和审批数据；管理员能看到待批准账号与第三方登录待关联数量。
- 接受、拒绝、撤回或批准后重新聚合，数量与列表立即更新。
- 亮色、暗色下待办卡片、空状态、操作按钮和原列表卡片均可读。
- 完整记录仍可从待办中心进入推送历史或组织架构。
