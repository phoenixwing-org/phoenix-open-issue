# Open Issue List 使用手册

> 汽车行业 IATF 16949 / 8D 标准议题追踪系统

## 快速开始

```bash
pnpm run dev     # 启动 server(:3400) + web(:5181)
```

本地开发默认管理员账号：`admin`，密码 `123456`。生产环境的初始密码由 `INITIAL_ADMIN_PASSWORD` 设置，且必须至少 12 位。

首次登录后，仪表盘会弹窗询问「是否添加演示数据？」，选择「添加演示数据」可一键生成示例列表、Issue、点检等，快速体验完整功能。选择「不需要」则只保留管理员账号，不再询问。

## 典型使用场景

### 场景一：个人点检表

> 比如杨腊梅需要一份自己的日常点检清单，自己管理、自己使用。

1. **创建列表**：仪表盘 → `+ 新建列表` → 名称填"杨腊梅的点检表"，类型选"自定义"
2. 创建者自动是 owner（所有者），自己一个人用，不需要额外添加成员
3. **新建 Issue**：进入列表 → `+ 新建 Issue` → 填写检查条目（如"检查设备A温度"）
4. **添加点检**：点击 Issue 进入详情 → `+ 添加点检` → 填写日期、描述、负责人
5. **日常使用**：每天打开列表，对点检项标记"完成"或"未完成"

### 场景二：小组点检表

> 测试组需要一份公共点检表，加入杨腊梅、宋蕾、林芝彤三人。

1. **创建列表**：仪表盘 → `+ 新建列表` → 名称填"测试组组点检"，类型选"月度"
2. **添加成员**：进入列表 → 点击「👥 成员」按钮 → 依次添加杨腊梅、宋蕾、林芝彤
   - 角色选 **编辑者**（可新建/编辑 Issue）或 **观察者**（只能查看）
3. **新建 Issue**：各成员在列表中创建自己负责的检查条目
4. **分配责任人**：创建 Issue 时指定负责人，明确谁负责处理

### 场景三：个人点检推送到小组

> 杨腊梅在自己的点检表中发现问题，需要推到测试组公共点检表。

1. 在杨腊梅的个人点检表中，找到需要推送的 Issue
2. 点击该 Issue 行右侧的 📤 图标（或进入详情页点「推送」）
3. 选择目标列表"测试组组点检"
4. 目标列表负责人收到推送审批通知
5. 审批通过后，该 Issue 出现在测试组公共点检表中

> 💡 推送是**建立列表关联**而非移动或复制。审批通过后，两个列表看到的是同一个 Issue，修改会反映到同一条记录。

## 基本概念

### Issue List（议题列表 / 点检表）

按年/月/项目组织的议题集合。每个列表有独立的成员和权限。

| 类型 | 说明 | 示例 |
|------|------|------|
| 年度 (`yearly`) | 年度检查计划 | 2026年度质量点检 |
| 月度 (`monthly`) | 月度常规检查 | 2026年7月点检 |
| 项目 (`project`) | 特定项目跟踪 | 新车型Q-2026-001 |
| 自定义 (`custom`) | 个人或临时列表 | 杨腊梅的点检表 |

### Issue（议题）

单个问题条目，包含 21 个汽车行业标准字段（严重度、分类、发现阶段、8D 报告等）。

### Checkpoint（点检）

每个 Issue 下的时间线节点，记录检查日期、描述、负责人和完成状态。逾期未完成的点检会自动红色高亮。

### 推送

将 Issue 从一个列表关联到另一个列表（如个人→小组、小组→科室）。需双方有共同成员，目标列表 owner/admin 审批后生效。

## 仪表盘

登录后首先看到的页面。

- **视图切换**：👤 我的 / 🌐 所有 / 📦 归档
- **列表卡片**：展示名称、类型标签、负责人、成员数、更新时间
- **点击卡片**：进入该列表的 Issue 管理页
- **📦 按钮**：归档列表（从默认视图隐藏，可在「归档」视图中点击「取消归档」恢复为正常状态）
- **+ 新建列表**：创建新列表

> 💡 打开的页面标签会在浏览器刷新后自动恢复，无需重新打开。

## 页面帮助与界面巡游

- 欢迎页点击「界面巡游」可查看 Ribbon、工作台标签、主内容区和状态栏。
- 各业务页面右上角的 `?` 提供当前页面说明；点击「本页导引」可按实际控件逐步查看新增、编辑、筛选、归档、软删除、恢复、审批等操作。

## 列表操作
### 列表查看
![列表管理表格.png](../images/列表管理表格.png)

列表管理把列表生命周期统一显示在「状态」列中，并提供 **全部 / 正常 / 已归档 / 已删除** 视图：

- **全部**：普通用户看到自己作为负责人或成员可访问的正常、已归档列表；系统管理员还会看到已删除列表。
- **正常**：当前用户权限范围内未归档、未删除的列表；系统管理员看到全系统正常列表。
- **已归档**：当前用户权限范围内的归档列表，可进入详情；有列表管理权限时可「取消归档」。
- **已删除**：仅系统管理员可见，可执行恢复。删除为软删除，不等同于归档。

列表管理支持按名称、描述、负责人搜索，并可按列表类型筛选。数据在前端筛选；默认每页 30 条，超过 30 条显示分页，可切换 30/50/100 条。筛选条件或状态视图切换时自动回到第 1 页。

### 筛选和排序

列表页支持：
- **状态筛选**：待处理 / 进行中 / 已解决 / 已关闭 / 已取消
- **优先级筛选**：低 / 中 / 高 / 紧急
- **严重度筛选**：致命 / 严重 / 一般 / 轻微
- **分类筛选**：外观 / 尺寸 / 功能 / 过程 / 安全 / 其他
- **文本搜索**：按 Issue 编号、标题或描述模糊搜索
- **只显示【不关注】**：勾选后列表**仅显示**关注度为 0 的 Issue；未勾选时默认隐藏不关注项
- **列头排序**：支持编号、严重度、优先级、**关注度**、计划完成日、状态、创建日期等；默认 **关注度降序 → 优先级（紧急优先）**
- **前端分页**：列表全部 Issue 会分批拉取后在前端筛选；默认每页 30 条，可切换 30/50/100

### 列表表格交互（v0.2.0）

| 区域 | 操作 |
|------|------|
| 标题 / 编号 | 点击 → 打开 Issue **详情**模态 |
| 严重度、优先级、状态、关注、责任人、功能、分类、发现阶段 | 点击 → **快速编辑**弹窗 |
| 操作列 | 🔍 详情 · ✏️ 编辑 · 📤 推送 · ⋮ 更多（不关注/恢复/删除） |
| 列设置 | 简单 / 复杂 / 跟踪 三视图分别配置显示列与顺序（本机 localStorage） |

### 成员管理

列表页 → `👥 成员` 按钮 → 管理成员

> 📖 **负责人与成员角色较复杂，请先阅读** [列表成员与负责人.md](./列表成员与负责人.md)（设计讨论稿）。

**角色与权限：**

系统权限优先于列表角色：系统管理员可跨列表管理；系统权限为**查看**时是全局只读上限，即使列表角色是 owner/editor 也不能写；系统权限为**编辑**时再按下表判断。

若 Issue 是从其他列表推送关联而来，主字段和点检的修改权限取决于**源列表角色**；当前目标列表的 editor 可调整本列表关注度，但不一定能修改 Issue 主数据。

| 角色 | 权限说明 |
|------|----------|
| **owner**（所有者） | 完全控制：编辑列表、管理成员、删除列表、转让主负责人 |
| **admin** | 管理成员、编辑列表设置 |
| **editor**（编辑者） | 新建/编辑/删除 Issue、添加点检 |
| **reporter** | 新建 Issue；不能修改已有 Issue 或点检 |
| **viewer**（观察者） | 只读查看，不能修改 |

> 创建者自动成为**主负责人**（列表「负责人」列所显示的人）。个人点检表不需要额外添加成员。小组点检表建议将组员加为 editor。
>
> **注意**：「添加成员 → 选所有者」与「转让主负责人」是不同操作，当前 UI 容易混淆——详见设计讨论稿。

### 归档 / 编辑 / 删除列表

- **归档**：仪表盘卡片右下角点击 📦，或在「列表管理」操作列点击「归档」，确认后执行；归档后从默认视图隐藏，但数据和访问权限不变
- **取消归档**：仪表盘切换到「归档」后点击「取消归档」，或在「列表管理 → 已归档」操作列点击「取消归档」，确认后恢复为正常状态
- **编辑**：列表页 → 编辑按钮 → 修改名称、描述
- **删除**：列表页 → 删除按钮（需确认，执行软删除；业务数据仍保留，可由系统管理员恢复）

> 「状态」列按 **已删除 > 已归档 > 正常** 的优先级显示。底层仍将归档和软删除分开记录：归档是日常可逆的整理状态，删除则进入仅系统管理员可恢复的保护状态。

## Issue 操作

### 新建 Issue

列表页 → `+ 新建 Issue` → 填写：

| 字段 | 说明 | 可选值 |
|------|------|--------|
| **标题** | 必填 | — |
| **严重度** | 问题严重程度 | 致命 / 严重 / 一般 / 轻微 |
| **优先级** | 处理优先级 | 低 / 中 / 高 / 紧急 |
| **问题分类** | 问题类别 | 外观 / 尺寸 / 功能 / 过程 / 安全 / 其他 |
| **发现阶段** | 在哪个环节发现 | 来料检验 / 过程检验 / 终检 / 客户反馈 / 审核发现 / 供应商端 |
| **提出人** | 谁提出的 | 从用户列表选择 |
| **责任人** | 谁负责处理 | 从用户列表选择 |
| **计划完成日** | 截止日期 | YYYY-MM-DD |

### 查看 Issue

点击 **标题** 或 **编号** → Issue 详情以遮罩弹窗形式打开，也可点击「页面模式」在独立标签页中打开（支持多标签、页面巡游）。

展示内容：

- **基本信息**：标题、状态、严重度、优先级、分类等
- **人员与日期**：提出人、责任人、计划完成日、实际完成日
- **关闭信息**：关闭理由、关闭人
- **8D 报告**：D3 遏制措施 / D4 根因分析 / D5-D6 纠正措施
- **描述**：详细描述
- **点检时间线**：所有点检记录，按日期排列
![](../images/Issue-查看.png)
### 变更状态

列表行 → `状态 ▾` 下拉 → 选择目标状态：

```
待处理 → 进行中 → 已解决 → 已关闭
  ↓                  ↓
已取消            （不可逆）
```

- **⊘ 不关注**：更多菜单 → 设为不关注（`attentionLevel=0`，列表默认隐藏）
- **🔄 恢复默认(三星)**：不关注行 → 更多 → 恢复默认
- 勾选 **「只显示【不关注】」** 可仅查看 level=0 的行（半透明）
- **🗑 删除**：暂禁用（点击提示"临时禁用"）

**关注度编辑**：列表关注列点击 → 五星弹窗；编辑 Issue 弹窗内也可调整（本列表级别，0~5 星，可清零为不关注）。

### 推送 Issue

- **列表行**：点击 📤 图标 → 选择目标列表 → 确认
- **详情页**：点击「推送」按钮 → 选择目标列表 → 确认

推送条件：发起人拥有源列表推送权限并可访问目标列表，双方列表有共同成员；目标列表 owner/admin 可审批。
![](../images/Issue-推送.png)
### 编辑 / 不关注 / 删除 Issue

- **编辑**：详情页或列表操作列 → 编辑
- **设为不关注**：列表行 → 更多 → 不关注（仅本列表隐藏，数据保留）
- **恢复默认三星**：勾选「只显示【不关注】」→ 更多 → 恢复默认
- **删除**：暂禁用中
![](../images/Issue-编辑.png)

## 点检操作

### 添加点检

Issue 详情页 → `+ 添加点检` → 填写：

| 字段 | 说明 |
|------|------|
| 日期 | 点检日期（逾期未完成会高亮） |
| 描述 | 检查内容描述 |
| 负责人 | 谁负责执行点检 |
![](../images/添加点检.png)
### 标记完成 / 取消完成

- 点检项 → 点击「✓ 标记完成」→ 状态变为已完成（绿色）
- 再次点击可「取消完成」恢复为待处理

### 删除点检

点检项 → 🗑️ 按钮 → 确认删除。

### 逾期提醒

点检日期已过且状态仍为"待处理"的项，会以**红色高亮**显示。

## 推送审批

### 发起推送（推送方）

1. 在 Issue 详情页或列表行点击「推送」
2. 选择目标列表
3. 确认推送
4. 推送记录以“待审批”状态进入目标列表

### 审批推送（接收方）

目标列表页出现黄色提示条，显示待审批数量：

1. 点击「推送收件箱」查看待审批推送
2. 对每条推送选择：
   - **接受** → 将同一个 Issue 关联到本列表，可正常查看；Issue 主数据仍归属源列表
   - **拒绝** → 填写理由，Issue 不会进入本列表
![](../images/审批推送.png)
也可以在「推送历史」页面统一查看和审批所有推送。
![](../images/推送历史.png)

## 组织架构

导航 → 「组织架构」页面 → 树形展示：

- **全部人员**（根节点）：汇总所有组织的人员
- **部门 (division)**：如研发部、质量部
- **小组 (group)**：如前端组、后端组

支持操作：
- 点击节点 → 查看该组织下的成员列表（有子节点时默认含下级组织，可通过复选框切换仅本级）
- **系统管理员**（`systemRole = admin`）可：新建/编辑/删除组织节点、审批用户、调整组织与权限、禁用/启用、编辑用户、重置密码
- **系统查看**（`systemRole = viewer`）是全局只读，即使其列表成员角色较高也不能修改业务数据
- 其他非管理员仅可浏览组织树与成员列表；具体列表操作由列表角色决定

新注册用户自动归入「待定组」，管理员在组织架构中调整归属并审批。

## 设置

导航 → 「设置」页面，使用 Tab 页签管理以下模块：

### 📚 数据字典

管理 Issue 的下拉选项枚举值：

| 字典分组 | 说明 |
|----------|------|
| 问题分类 | Issue 的分类选项 |
| 发现阶段 | 发现环节选项 |
| 组织类型 | 组织层级选项 |
| 严重度 | 严重度选项 |
| 关闭理由 | 关闭理由选项 |

系统管理员可执行以下写操作；其他用户可查看字典内容：
- **🚗 汽车默认值**：一键追加 IATF 16949 行业标准预设
- **💻 软件默认值**：一键追加软件行业预设
- **+ 添加**：自定义新的下拉选项
- **🗑 删除一类值**：按标签（汽车/软件）批量删除该类所有字典项，无引用的删除、有引用的跳过
- **启用/禁用**：控制选项是否在下拉菜单中出现
- **删除**：移除单个选项（已被 Issue 使用的项无法删除）

### 🔑 修改密码

修改当前登录用户的密码。

### 💾 数据备份

系统管理员可以使用两种完整导出：

- **备份导出**：包含全部业务数据，不含密码哈希；导入后所有用户密码重置为部署配置 `INITIAL_ADMIN_PASSWORD`。
- **迁移导出**：用于 SQLite → PostgreSQL 等迁移；保留非 `admin` 用户的密码哈希，导入后仅 `admin` 重置为 `INITIAL_ADMIN_PASSWORD`。该文件属于敏感凭据，应在迁移后安全删除。

系统管理员才可以导入数据。普通用户只能导出自己可访问列表及其 Issue、点检、链接和相关推送；文件不包含用户、组织、字典或功能数据，也不能导入数据库。

数据导入会撤销导入前签发的旧登录令牌，用户需要重新登录。

### 🔧 数据库修正

补建缺失的 Issue 链接记录（`issueListLinks`）。如果列表 Issue 数量异常，可在此一键修正。

## 用户注册

登录页 → `没有账号？去注册` → 填写用户名、邮箱、密码、显示名。

新用户注册后需管理员审批才能登录。管理员在「组织架构」页面审批用户并分配组织归属。

启动、升级或补种字典不会自动批准待审批账号。账号被禁用、撤销审批或密码变更后，旧登录令牌立即失效，需要重新登录。

## 单元测试

Ribbon → **系统** → **单元测试**（需系统管理员）：

1. 页面列出当前 Vitest 纳入的测试文件（如 core 算法 3 个 + tests 1 个）及用例数
2. 点击 **全部运行** → 后台执行 `vitest run`（与根目录 `pnpm test` 等价）
3. 完成后点击 **查看 HTML 报告（新标签页）** → 在独立浏览器页面查看结果（不内嵌于应用框架）

> 仅开发/内网环境可用；生产部署若无 `node_modules/vitest` 会提示不可用。

命令行仍可直接运行：`pnpm test`

## 常见问题

### Q: 个人点检表和小组点检表有什么区别？

本质上都是 Issue List，区别在于：
- **个人**：只加自己（创建者即 owner），其他人看不到
- **小组**：添加多个成员（如测试组全员），每个人都能看到和操作

### Q: 怎么把个人点检的内容推到小组？

使用「推送」功能。在自己的列表中点击 Issue 的 📤 图标，选择目标小组列表即可。

### Q: 推送后原列表的 Issue 会消失吗？

不会。推送是**关联**，不是移动；审批通过后两个列表看到同一个 Issue。Issue 的主数据由源列表权限控制，目标列表拥有自己的关注度等列表级信息。

### Q: 点检逾期了怎么提醒？

逾期点检项会自动以红色高亮显示。在「跟踪」视图（📋📋📋）中可以看到每个 Issue 最近的点检状态。

### Q: 怎么重置所有数据重新开始？

删除 `data/open-issue.sqlite` 文件后重启服务，数据库会自动重建并创建管理员账号。首次登录仪表盘时会弹窗询问是否添加演示数据。
