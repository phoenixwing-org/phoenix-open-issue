# Phoenix Admin 插件迁移审计

状态：template active / Issue interim

详细审计底稿和多插件纵向统计后续放到 `phoenix-ai-workspaces`；本文件只保留源码仓库需要共同遵守的统计口径、当前 Issue 快照和验收结论。

## 1. 统一报告模板

每个迁移项目必须按相同顺序报告，并把数字标为“实测”“估算”或“待测”。

### A. 身份与基线

- 项目、插件 `moduleId`、版本；
- 不可变 legacy commit；
- Host、Wing、COOL 兼容版本；
- 统计日期和复算命令。

### B. UI 保真

- legacy 与插件的路由 View 数、业务组件数和 UI 源码行数；
- template/style 完全一致数、允许差异数、未经批准差异数；
- 浏览器截图和关键交互回归结果；
- 未迁移页面及其归属理由（插件、Host、淘汰）。

### C. 算法与单元测试

- 迁移的纯算法文件/行数；
- 继承、增加、删除的测试文件和测试用例数；
- 算法是否仍依赖 Vue、Host、网络或数据库；
- 类型检查、单测、契约测试和构建结果。

### D. 框架复用

逐项列出身份、用户、部门、字典、文件、路由、菜单、权限、审计、任务、备份和 Wing 区域贡献：

1. legacy 自建实现；
2. COOL/Wing/Pah 替代能力；
3. 插件保留的 adapter；
4. 被消除的文件/行数；
5. 仍需插件拥有的领域规则；
6. 验证证据。

### E. 规模与交付物

必须同时报告，不能把其中一种体积冒充另一种：

- 源码文件数、物理行、非空行、UTF-8 字节；
- 插件压缩包大小；
- 安装后磁盘大小；
- 前端增量 chunk 原始/gzip/brotli；
- 后端产物与 migration 大小；
- peer dependency 与实际被重复打包的 dependency；
- 新增 Host adapter 成本与未迁移平台壳收益。

### F. 复杂度趋势

- 本插件从零搭建耗时；
- 使用共享脚手架后新增一个 View、API、Entity 的改动文件数；
- 相比前一个插件，专用 adapter 行数和重复配置是否下降；
- 每千行业务代码的测试用例数；
- 下一插件可直接复用的脚本、Fixture、Action 或 npm 包。

### G. 结论

- `pass`：UI/算法/关键交互无未解释回退，接口闭环，数字可复算；
- `conditional pass`：迁移切片已验证，但后端或交付包仍有明确待办；
- `fail`：重做 UI、丢算法、复用造成领域语义损失，或统计不可复算。
