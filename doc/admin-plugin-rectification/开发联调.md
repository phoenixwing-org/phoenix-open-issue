# Phoenix Admin 开发联调

状态：active

完整部署入口见 [Phoenix Admin 插件部署](../PhoenixAdmin插件部署.md)。本页补充 Admin 整改阶段的命名、挂载原理和联调背景；开发目录挂载不等同于正式安装。Windows 必须按部署入口使用普通权限 Junction 脚本并校验 `LinkType=Junction`，本页不重复维护 PowerShell 命令。

## 1. 命名边界

| 用途 | 固定值 | 原因 |
| --- | --- | --- |
| 源码目录 | `phoenix-open-issue` | 避免与第三方 COOL 模块目录重名 |
| Pah `moduleId` | `phoenix-open-issue` | 作为插件、路由 ID、能力码和 API 的唯一技术命名空间 |
| 产品 URL | `/open-issue/*` | 面向用户保持短、稳定、易输入 |
| Manifest `routePrefix` | `/open-issue` | 显式把产品 URL 与技术 ID 解耦 |
| API 前缀 | `/admin/phoenix-open-issue/*` | 后端接口仍使用唯一技术命名空间 |

开发查看入口：<http://127.0.0.1:9000/open-issue/>。插件前端模块提供根路径重定向，实际列表路由为 `/open-issue/lists`。

不要使用 `/pheonix-open-issue/`：除了过长，`phoenix` 也容易拼写错误；厂商前缀不应暴露给普通用户。

## 2. 本地开发挂载

macOS/Linux 在 Open Issue worktree 执行：

```bash
pnpm admin-plugin:mount-dev-host
```

脚本只在目标不存在时创建以下本地软链接；Windows 权威脚本创建同位置的 Junction。两者遇到真实目录或指向其他位置的链接都会拒绝覆盖：

```text
phoenix-admin-vue/src/modules/phoenix-open-issue
  -> phoenix-open-issue/packages/admin-plugin/vue/phoenix-open-issue

phoenix-admin-node/src/modules/phoenix-open-issue
  -> phoenix-open-issue/packages/admin-plugin/midway/phoenix-open-issue
```

插件自己的普通运行依赖（当前为 `driver.js`）从插件仓的 `node_modules` 本地桥接到 Vue Host 的 `node_modules`；它们不会写入 Host 的 `package.json` 或锁文件。Vue、Vue Router、Pinia、Element Plus 和 Phoenix Wing 仍是 Host 提供的 peer 单例，不建立第二份运行时。

插件源码始终归档在 Open Issue 仓库。脚本会把两个挂载点的精确路径写入各自 Host 仓库的本机 `.git/info/exclude`，因此目录挂载不会出现在 Host 的 `git status`，产品名也不会进入 Host 的 tracked `.gitignore` 或提交历史。

不要把插件源码复制进 Host 后依靠 `.gitignore` 隐藏。那会让本机存在一份无法审计、容易过期的业务副本。开发挂载必须保持“Host 只有链接，插件仓是唯一源码真源”。

检查或移除挂载：

```bash
pnpm admin-plugin:status-dev-host
pnpm admin-plugin:unmount-dev-host
```

卸载命令只删除确认仍指向本插件源码的目录挂载，并同步移除本机 exclude 标记；它拒绝删除真实目录或其他链接。Windows 的 Status/Unmount 命令继续以 [Phoenix Admin 插件部署](../PhoenixAdmin插件部署.md) 为准。

## 3. 本机 Manifest 登记

源码挂载与插件治理分开：

1. 启动 Phoenix Admin Node 和 Vue；
2. 以 Host 根管理员登录；
3. 打开 `/pah/plugins`；
4. 粘贴 `packages/admin-plugin/manifest.json`，依次执行“校验并登记”“安装”“启用”；
5. 重新登录或刷新权限菜单后访问 `/open-issue/lists`。

登记结果、菜单贡献和角色授权只写入本机开发数据库，不写入 Host Git。停用会撤销菜单贡献；卸载默认保留插件业务数据。当前插件还没有迁入 Midway Controller/Service/Entity，因此启用后可以验证页面、路由和布局，业务数据接口尚不会闭环。

Host Vite 使用 `resolve.dedupe` 保证 Vue、Pinia、Element Plus 和 Phoenix Wing 复用 Host 单例。新增或移除链接后必须重启开发服务器；普通插件前端源码修改应由 Vite HMR 接管。

## 4. 验证命令

Admin 插件仓库：

```bash
pnpm admin-plugin:verify
```

Phoenix Admin Vue：

```bash
pnpm run type-check
pnpm run build
```

两个 Host 仓库还必须满足：

```bash
git status --short
git check-ignore -v src/modules/phoenix-open-issue
```

第一条不得因为插件挂载新增业务文件，第二条必须指向本机 `.git/info/exclude`，不能指向 tracked `.gitignore`。

Phoenix Admin Node 的 `Pah 插件契约` 定向测试覆盖 `routePrefix`：唯一 `moduleId=phoenix-open-issue` 可以声明短路径 `/open-issue`，多段或畸形前缀必须拒绝。
