# 设置能力迁移边界

## 结论

legacy 的“设置”页是独立 Web 的平台壳，集中承载了数据字典、账号、登录、备份、数据库修正和 Function 导入。转为 Phoenix Admin 插件后不能整页照搬数据所有权，但必须逐项点检，保证能力有明确去向。

| legacy 分区 | 插件化归属 | 本轮处理 | 验收口径 |
| --- | --- | --- | --- |
| 数据字典 | Cool Host 字典 | 复用，不复制 `dictItems` 表 | Issue 的 7 个分组能从 Host 字典加载；维护入口使用“字典管理” |
| 修改密码 | Cool Host 用户与认证 | 不迁移 | 使用 Phoenix Admin 个人账号能力，不出现第二套密码 API |
| 登录方式 | Cool Host 登录与第三方认证 | 不迁移 | 插件不保存 token、登录策略或第三方身份 |
| 数据备份 | Pah 迁移备份门禁 + 插件数据所有权清单 | 不迁移 legacy 整库导入；已完成隔离 PostgreSQL 恢复演练 | 只恢复插件表，不覆盖 Host 用户、字典和菜单；生产执行必须由可信验证器核对备份证明 |
| 数据库修正 | Open Issue 插件 | 保留 | 只执行插件声明的幂等任务；当前为点检数据和 Issue 链接修正 |
| Function 导入 | Open Issue Function View | 已迁到独立“功能”页 | XLSX 预览、导入、JSON 导出、停用与恢复均在功能页完成 |
| View 显示偏好 | 浏览器本机设置 | 保留现有 Store | 列顺序、列宽、时间线排序/形式等继续保存在本机，不写业务表 |

## Host 字典映射

Issue 只保存稳定值，显示名从 Cool 字典读取。当前映射范围：

1. 问题分类 `issueCategory`
2. 发现阶段 `detectionPhase`
3. 组织类型 `orgUnitType`
4. 重要度 `severity`
5. 紧急度 `priority`
6. 关闭理由 `closeReason`
7. 点检表类型 `listType`

插件前端通过 Host 字典服务读取并转换为 legacy `DictItem` 外形；不在插件仓复制 Host 字典实体、控制器或设置页。插件卸载后，Host 字典仍属于 Host，不能随插件数据清除。

## 数据库修正保留范围

插件当前公开两个幂等任务：

- 点检数据修正：规范状态、顺序、审计时间和空截止日；不捏造截止日期。
- Issue 链接修正：补原始归属链接、去重并校正关联计数。

legacy 的 SQLite 表结构补全、旧用户角色补全、旧字典表去重、旧飞书表创建等任务不迁移；这些对象改由 PostgreSQL TypeORM 实体或 Cool Host 管理。开发环境可以使用 TypeORM `synchronize` 发现实体，但生产环境明确关闭 `synchronize`。

当前插件已升级 manifest v2，并随包提供 `migrations/0001-bootstrap.sql` 与 SHA-256；Pah `9c6f298` 负责制品一一对应校验、只读 dry-run、一次性 plan、事务执行和 migration ledger。DDL 默认不会从普通安装接口执行，缺少可信备份验证器时安全拒绝。2026-08-02 已在两个专用临时 PostgreSQL 数据库完成 `建表 → 8 表演示数据 → pg_dump → 恢复 → 黄金查询` 演练，恢复结果为 8 张表、43 个索引、8 条记录，随后删除临时数据库并复查为 0。该演练关闭“无恢复路径”门禁，但不能替代正式发布窗口的备份证明和恢复责任人。

维护页的数据修正仍不能替代结构迁移；前者只处理已有 `oip_` 表内的幂等数据问题。

## 页面处理规则

1. 业务 View 原样迁移；平台壳能力逐项映射，不能因为“不复制设置页”而漏掉能力。
2. Host 已有的设置只提供明确入口或文档，不在插件内再做一套表单。
3. 插件专属维护能力放在 Open Issue 管理域，Function 不再藏在设置页。
4. 每个未迁移项必须写明替代入口、数据所有者和用户点检方式。
