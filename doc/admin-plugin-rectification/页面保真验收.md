# 页面保真验收

状态：active

## 1. 当前金线

以下内容共同构成已经确认的页面金线：

- 代码：`legacy/2cdc5ea`；
- 当前 `admin` 插件包中的业务 View，必须由批量映射脚本追溯到该提交；
- 截图：仓库 `images/` 下的列表、Issue、点检、推送等图片；
- 行为：现有测试、使用手册和页面帮助文本。

截图不只用于比颜色，还用于约束信息密度、列顺序、按钮位置、弹层形态和同屏可见内容。

迁移第一遍还应增加代码级金线：业务页面的 template 和 scoped style 原则上保持原文；如因 Host 挂载必须改动，应逐处记录原因。第一遍不接受以“接口已经不同”为理由同时改写页面。

## 2. 允许变化

以下属于插件接入所需变化，可以在保真验收中单独标注：

- 外层由独立 `AppShell` 改为 Phoenix Admin Host / Wing 壳；
- 登录、退出、用户与部门管理入口改由 Host 提供；
- 路由增加 `/open-issue/*` 前缀，API 改为 `/admin/phoenix-open-issue/*`；
- 用户 ID 和部门 ID 改为 Host 标识；
- 页面标题、Tab 和菜单由 Host 注册；
- 全局通知、确认框、文件、字典等通过 Host SDK 调用；
- 颜色和字体可继承 Host token，但不能造成信息层级和布局变化；
- 独立版系统级设置、组织管理、登录和测试入口不随插件迁入。

## 3. 未经单独确认不允许变化

- 把页面内筛选器移到 Primary、侧栏或抽屉；
- 把 Issue 点检时间线移到 Secondary 或 Bottom；
- 新增与原页面无关的 Properties 双栏布局；
- 把原弹层改成整页，或把整页改成弹层；
- 改变列表列集合、默认顺序、宽度策略、固定列和操作入口；
- 合并、拆分或改名业务动作；
- 用新卡片/表单重新表达原有详情页；
- 因为 Host 已有某个通用组件，就改变 Open Issue 原有业务语义；
- 同时进行响应式重构、视觉升级或交互“优化”。

这些变化并非永远禁止，但必须脱离插件迁移任务，作为独立产品需求评审。

## 5. 不直接迁入插件导航的独立版页面

以下页面是否保留，应按能力归属决定，而不是按“页面长得不一样”决定：

| 独立版页面 | Admin 插件建议 |
|---|---|
| 登录、OAuth 回调 | 不迁入；完全使用 Host 身份与会话 |
| 组织架构/用户管理 | 不迁入；使用 Host 用户与部门页面 |
| 全局显示设置 | 不迁入；使用 Host/Wing 显示偏好 |
| 数据库修复、备份 | 入口归 Host；插件只贡献自身表、检查和恢复钩子 |
| 单元测试页面 | 不进入普通产品菜单；转为插件诊断/健康检查 |
| 欢迎页 | 不创建第二个全局欢迎层；可在插件中心提供模块说明 |
| 功能表 | 先单独确认它是 Open Issue 领域能力、Function 插件能力还是迁移兼容入口 |

这类页面被 Host 能力替代，不属于“重新设计 Open Issue 业务页面”。

## 6. 验收方法

每个垂直切片至少保留四类证据：

1. **视觉对照**：同一数据、同一视口下的基线截图与 Host 插件截图；
2. **交互清单**：按钮、筛选、排序、分页、弹层、快捷编辑和返回路径逐项核对；
3. **权限矩阵**：Host capability 与 `owner/admin/editor/reporter/viewer` 组合结果；
4. **数据/API 对照**：字段、默认值、字典标签、错误状态和审计关联一致。

建议把验收分为两个独立关卡：

- **关卡 A：原样页面已进入 Host。** 使用兼容 facade 或模拟数据，先证明页面结构、样式和交互没有变；此时不要求已经使用最终 Host API。
- **关卡 B：接口已经切换。** 在关卡 A 的页面金线不变前提下，验证 Host actor、用户/部门、字典、API、资源权限和审计。

关卡 A 未通过时不得进入关卡 B。这样接口问题不会被误判成需要重新设计页面。

当前关卡 A 的代码级结果：仪表盘、列表管理、列表详情、Issue 详情、推送弹层、推送历史、8D 报告及其依赖组件共 25 个 Vue 文件，template/style 与 `legacy/2cdc5ea` 逐文件完全一致。

验收顺序应是先功能和信息结构，再处理 Host token 与细节样式。不能用“功能大致可用”替代页面保真。
