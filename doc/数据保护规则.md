# 数据保护规则（临时方案）

> 生效日期：2026-06-30
> 范围：前端 UI 层控制，后端保留接口

## 原则

**进入数据库的数据永不可物理删除，只做软标记。**

## 规则明细

| 数据类型 | 原操作 | 替代方案 | 状态字段 |
|---------|--------|---------|---------|
| Issue | 删除 | 变更状态为「已取消」 | `status = 'cancelled'` |
| Issue List | 删除 | Dashboard 归档 | `archived = 1` |
| Checkpoint（点检） | 删除 | 标记为「已跳过」 | `status = 'skipped'` |
| OrgUnit（组织节点） | 删除 | 暂时隐藏删除按钮 | — |
| User（用户） | 删除 | 拒绝即禁止登录 | `approved = 0` |
| PushRecord（推送记录） | — | 保留完整审计日志 | — |

## 实施范围

- **前端**：删除按钮已从 UI 移除
- **后端**：删除接口保留但不暴露调用入口
- **DB**：无外键，保留所有关联数据

## 后续计划

正式版用 `is_deleted` 软删除字段 + 时间戳统一标记，配合 UI 筛选「显示/隐藏已作废」。
