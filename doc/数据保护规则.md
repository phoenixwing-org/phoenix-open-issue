# 数据保护规则（临时方案）

> 生效日期：2026-06-30；后端强制日期：2026-07-11
> 范围：前端 UI + 后端 Service/API

## 原则

**进入数据库的数据永不可物理删除，只做软标记。**

## 规则明细

| 数据类型 | 原操作 | 替代方案 | 状态字段 |
|---------|--------|---------|---------|
| Issue | 删除 | 变更状态为「已取消」 | `status = 'cancelled'` |
| Issue List | 删除 | 软删除或 Dashboard 归档 | `isDeleted = 1` / `archived = 1` |
| Checkpoint（点检） | 删除 | 标记为「已跳过」 | `status = 'skipped'` |
| OrgUnit（组织节点） | 删除 | 后端拒绝；迁移成员后改名标识停用 | — |
| User（用户） | 删除 | 禁用账号 | `disabled = 1` |
| 功能 | 删除 | 停用，保留 Issue 历史关联 | `enabled = 0` |
| 数据字典 | 删除 | 停用；维护型去重除外 | `enabled = 0` |
| PushRecord（推送记录） | — | 保留完整审计日志 | — |

## 实施范围

- **前端**：业务数据删除入口改为取消、跳过、停用或归档
- **后端**：旧 DELETE 接口为兼容保留，但执行软状态变更；组织删除直接拒绝
- **DB**：无外键，保留所有关联数据

数据字典去重和数据库修复属于维护操作，可物理清除重复技术记录；不得删除业务记录。

## 后续计划

正式版统一软删除字段、时间戳和操作人，并增加审计日志。
