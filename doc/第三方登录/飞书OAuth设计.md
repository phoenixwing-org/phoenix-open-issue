# 飞书 OAuth 登录与账号绑定设计

> **状态说明（2026-07-20）**  
> 安全原则、身份字段、登录票据与租户策略仍适用。  
> **§3.1「用户自助绑定」已废止**，现行为「飞书登录 → 待审查 → 仅管理员绑定/新建」。详见 [管理员绑定与待审查计划.md](./管理员绑定与待审查计划.md) 与 [README.md](./README.md)。

## 1. 设计原则

- 本地用户是权限、组织、审批和数据归属的唯一主体。
- 飞书身份只是登录凭证，不直接承担本项目权限。
- 只有服务端接触 `client_secret`、授权码和飞书访问令牌。
- 登录、绑定、解绑是不同目的的操作，必须分别授权、分别校验。
- 所有身份匹配都使用提供方返回的稳定 ID，不用邮箱、手机号或姓名推断。
- 未启用或配置不完整时，前端不显示飞书登录入口。

## 2. 飞书身份字段

飞书用户信息可能返回：

- `open_id`：同一用户在特定应用内的标识，不同应用的 `open_id` 不同。
- `union_id`：同一开发者主体下跨应用识别用户的标识。
- `user_id`：租户内的用户标识，同一租户内跨应用一致，不同租户可能不同，且读取可能需要额外权限。
- `tenant_key`：飞书租户标识。
- 姓名、头像、邮箱和手机号：只作为展示与审计快照，不作为自动绑定依据。

首期以 `provider=feishu` 和 `providerSubject=${tenant_key}:${open_id}` 唯一识别身份。保存 `tenant_key` 可以阻止其他租户的同名或同 ID 用户绕过允许租户策略。

## 3. 登录与绑定流程

### 3.1 绑定已有账号（superseded）

> **已废止（2026-07-20）**：不再支持设置页自助 `link/start`。  
> 现行：未绑定用户飞书登录后进入 `externalBindRequests`；管理员在组织页绑定已有用户或新建用户。见 [管理员绑定与待审查计划.md](./管理员绑定与待审查计划.md)。

以下为历史首期流程，仅供对照：

1. ~~用户先通过账号密码登录本系统。~~
2. ~~用户进入“个人设置 → 登录方式”，点击“绑定飞书”。~~
3. ~~前端请求 `POST /api/auth/oauth/feishu/link/start`。~~
4. ~~…（服务端 link 事务）~~

### 3.1b 现行：待审查与管理员绑定（摘要）

1. 用户在登录页发起飞书登录（`purpose=login`）。
2. 回调后若无 active `externalIdentities`，upsert `externalBindRequests`，前端展示待审查并可选补填拟用用户名/姓名。
3. 管理员在组织架构「第三方登录待审查」中：修改拟用字段 → 绑定已有用户，或新建账号并绑定（双重用户名查重，`linkSource=admin`）。
4. 用户再次飞书登录 → 签发一次性票据 → 换本项目 JWT。

### 3.2 使用飞书登录

1. 登录页从 `GET /api/auth/providers` 读取已启用提供方；只有服务端配置有效时才显示“使用飞书登录”。
2. 前端请求 `GET /api/auth/oauth/feishu/start?returnTo=/dashboard`。
3. 服务端创建目的为 `login` 的 OAuth 事务并返回 `authorizationUrl`，前端再跳转到飞书授权页。
4. 回调时服务端校验并消费 `state`，交换令牌、读取用户信息并校验租户。
5. 按 `provider + providerSubject` 精确查找 `externalIdentities`。
6. 若未绑定：写入/更新待审查 `externalBindRequests`，前端引导补填并等待管理员（不再提示「请先本地登录再自助绑定」）。
7. 若已绑定，继续检查本地用户是否审批通过、是否禁用。
8. 服务端生成 2 分钟内有效、只能使用一次的登录票据，回调重定向到前端 `/oauth/callback?ticket=...`。
9. 前端通过 `POST /api/auth/oauth/exchange-ticket` 换取本项目现有 JWT，再按普通登录流程保存会话。

回调 URL 中只允许出现一次性票据，不允许出现本项目长期 JWT、飞书 access token 或 refresh token。

### 3.3 解除绑定

1. 用户在“登录方式”中点击解除绑定。
2. 界面显示确认提示，明确解除后不能再用该飞书账号登录。
3. 服务端重新校验当前用户和身份归属。
4. 若用户没有可用本地密码且这是最后一个有效登录身份，则拒绝解除，避免账号被锁死。
5. 将身份状态改为 `revoked` 并记录操作者、时间和审计事件。必要时递增本地用户 `tokenVersion` 使现有会话失效。

管理员撤销绑定遵循相同规则，但需记录管理员 ID 和原因。

## 4. 建议接口

### 公开接口

| 方法 | 地址 | 说明 |
| --- | --- | --- |
| `GET` | `/api/auth/providers` | 仅返回已启用提供方的公开名称、按钮文案和图标标识 |
| `GET` | `/api/auth/oauth/:provider/start` | 创建登录事务并返回授权地址，`returnTo` 只接受站内白名单路径 |
| `GET` | `/api/auth/oauth/:provider/callback` | 服务端 OAuth 回调，不向前端暴露授权码 |
| `POST` | `/api/auth/oauth/exchange-ticket` | 原子消费一次性票据并签发本项目 JWT |

### 已登录用户接口

| 方法 | 地址 | 说明 |
| --- | --- | --- |
| `GET` | `/api/auth/external-identities` | 查看当前用户已绑定登录方式 |
| `POST` | `/api/auth/oauth/:provider/link/start` | 创建绑定事务，事务中固化当前 `userId` |
| `DELETE` | `/api/auth/external-identities/:id` | 确认后解除绑定，校验不能删除最后一种登录方式 |

### 管理接口

- 在组织用户详情中显示提供方、租户、绑定时间、最后登录时间和状态。
- 管理员可撤销异常绑定，但不能读取提供方密钥或令牌。
- 所有管理操作沿用现有系统管理员/组织权限校验。

## 5. 提供方扩展接口

建议未来代码目录：

```text
packages/server/src/auth/providers/
├── types.ts
├── registry.ts
└── feishu/
    └── FeishuAuthProvider.ts
```

提供方实现至少负责：

```ts
interface ExternalAuthProvider {
  id: string
  enabled: boolean
  createAuthorizationUrl(state: string): string
  exchangeCode(code: string): Promise<ExternalTokenResult>
  getIdentity(accessToken: string): Promise<ExternalIdentityProfile>
}
```

控制器只处理通用事务、会话签发和错误映射；飞书 URL、请求格式和字段转换集中在 provider 内。

## 6. 安全约束

### OAuth 事务

- `state` 至少使用 32 字节密码学随机数，数据库只存哈希，校验成功时原子标记为已使用。
- 事务默认 10 分钟失效；飞书授权码本身有效期更短且只能使用一次。
- 当前飞书授权端文档支持 PKCE，但网页换票指南未列出 `code_verifier` 字段；首版使用服务端 App Secret 和单次 `state`，待官方换票接口明确字段后再启用 PKCE，避免发送未文档化参数导致无法换票。
- `purpose=login` 的事务不能用于绑定，`purpose=link` 的事务必须固化发起用户。
- 相同 `state`、授权码和一次性票据都不能重放。
- 生产回调必须使用 HTTPS，并与飞书开放平台安全设置中的回调地址完全一致。

### 密钥与令牌

- `FEISHU_APP_SECRET` 只存在服务端环境变量或密钥系统，不进入前端构建产物、数据库、备份和日志。
- 授权码、access token、refresh token、PKCE verifier 和登录票据不得记录到访问日志或错误日志。
- 登录用途不申请 `offline_access`，也不保存 refresh token。
- 如果将来需要代表用户调用飞书 API，应另建加密令牌表、独立密钥和撤销流程，不能复用身份表明文字段。

### 用户与租户

- 默认必须配置允许登录的 `tenant_key`；空允许列表在生产环境视为配置错误，而不是允许所有租户。
- 未绑定身份、被撤销身份、未审批用户和已禁用用户均不能登录。
- 不根据邮箱、手机号或姓名自动绑定、合并或恢复账号。
- `returnTo` 只允许预定义站内路径，防止开放重定向。
- 对开始授权、回调、票据交换和解绑接口做速率限制。

### 审计

记录以下事件，但不记录敏感凭证：

- 授权开始、取消、回调成功和失败原因分类。
- 绑定、解绑、管理员撤销以及操作者。
- 第三方登录成功、身份未绑定、租户不允许、本地用户不可用。
- 身份的 `lastLoginAt` 和 `lastSyncedAt`。

## 7. 异常处理

| 场景 | 处理 |
| --- | --- |
| 用户拒绝授权 | 回到登录或设置页，显示“已取消授权”，不记为系统故障 |
| `state` 缺失、过期或已使用 | 拒绝请求并记录安全审计，不继续换取令牌 |
| 授权码交换失败 | 显示可重试提示，不暴露飞书原始令牌响应 |
| 租户不在允许列表 | 拒绝绑定/登录，提示联系管理员 |
| 身份未绑定 | 不创建账号、不猜测用户，提示先登录本地账号绑定 |
| 身份已绑定其他用户 | 拒绝绑定，交由管理员核对和撤销旧绑定 |
| 本地用户未审批或已禁用 | 沿用现有登录错误和审计规则 |
| 飞书服务暂时不可用 | 保留本地登录入口，提供稍后重试提示 |

## 8. 后续可选能力

- 管理员邀请后允许首次飞书登录创建“待审批用户”。
- 通过明确管理操作把待审批身份关联到组织和角色。
- 多飞书应用或多个租户配置。
- 企业自建应用中的组织/部门同步。
- 其他 OAuth/OIDC 提供方。

这些能力都不能改变首期原则：外部身份负责认证，本地用户负责授权。
